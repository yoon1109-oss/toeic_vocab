|------|------|
| Problem | 카드를 넘기는 노출 학습만 있어 실제로 외웠는지 확인할 수단이 없고, 저장되는 것은 위치 진도뿐이라 "내가 아는 단어 수"를 알 수 없다 |

| Core Value | 수동적 넘기기에서 능동적 확인 학습으로 전환하고, 취약 단어를 사용자가 고르지 않아도 자동으로 걸러낸다 |

## 1. User Intent Discovery (Phase 1)

### 핵심 문제
현재 앱의 학습은 전부 노출 기반이다. `nextWord()`로 카드를 넘기고 10개를 다 보면
`CompletionView`가 "잘했어요"를 띄우는 것으로 끝난다. 사용자는 방금 본 10단어 중
무엇을 기억하고 무엇을 잊었는지 알 방법이 없다.

또한 SharedPreferences에 저장되는 것은 위치 진도(`prog_set_index`, `prog_word_index`)뿐이며,
학습 성취를 나타내는 지표가 존재하지 않는다.

### 타깃 사용자
TOEIC/OPIc를 혼자 준비하는 최종 사용자. 관리자·개발자용 기능이 아니다.

### 성공 기준
1. 세트 완료 시 퀴즈 10문항이 출제되고, 각 문항은 정답 1개 + 서로 다른 오답 3개를 갖는다
2. 오답 단어가 별표에 추가되고, 이미 별표였던 단어가 해제되지 않는다
3. 퀴즈 모드 토글 OFF 시 기존 `CompletionView` 동작이 완전히 동일하게 유지된다
4. 토글 상태가 앱 재시작 후에도 유지된다
5. 신규 콘텐츠 데이터 제작 없이 기존 데이터만으로 동작한다

### 제약 조건
- **신규 콘텐츠 제작 금지**: 기존 3,000단어(뜻 포함)로 오답 선택지를 생성한다
- **기존 학습 흐름 보존**: 토글 OFF가 기본 동작과 100% 동일해야 한다
- 오프라인 동작 유지 (네트워크 의존 없음)

## 2. Alternatives Explored (Phase 2)

| 접근 | 신규 화면 | 발견성 | 작업량 | 결정 |
|------|-----------|--------|--------|------|
| **A. 세트 완료 직후 퀴즈** | 1개 | 높음 (흐름에 내장) | 소 | **채택** |
| B. 드로어 독립 퀴즈 모드 | 3개 | 낮음 (능동 탐색 필요) | 중 | 보류 |
| C. 카드 뒤집기 셀프 체크 | 0개 | 높음 | 최소 | 기각 |

### 채택: A안 + 드로어 퀴즈 모드 토글

**채택 이유**
- 신규 기능의 최대 리스크는 "아무도 쓰지 않는 것"이다. A안은 사용자가 기능을 찾아가지
  않아도 학습 흐름에서 자연히 만나게 되므로 이 리스크를 구조적으로 회피한다
- 문제 풀 대상이 "방금 본 10개"로 자동 결정되므로 범위 선택 화면이 필요 없다 → MVP 최소화
- 오답을 기존 별표(즐겨찾기) 기능에 흘려보내면 복습 동선이 이미 있는 기능으로 이어진다
- A안의 퀴즈 엔진(`QuizGenerator` + `QuizController`)을 만들어 두면, 나중에 B안의 독립
  퀴즈 모드는 진입 화면만 추가해서 얹을 수 있다

**기각 이유**
- B안: 화면 3개가 늘고 사용자가 능동적으로 찾아가야 해 초기 이용률이 낮을 위험이 크다
- C안: 객관적 채점이 없어 자기 기만이 가능하고, 점수라는 성취 지표가 생기지 않는다

**사용자 추가 요구 반영**: 드로어에 퀴즈 모드 온·오프 토글을 넣는다. 이는 A안의 유일한
단점(완료 축하 화면이 시험으로 바뀌는 피로감)을 사용자 선택으로 해소한다.

## 3. YAGNI Review (Phase 3)

### MVP 포함
| 항목 | 근거 |
|------|------|
| 영→한 4지선다 (10문항) | 핵심 문항 유형. 카드 학습 방향(영어 → 뜻)과 일치 |
| 즉시 정답/오답 피드백 | 선택 직후 정답을 색으로 표시. 학습 효과의 핵심 |
| 오답 자동 별표 추가 | 기존 `FavoriteService` 재활용. 구현 비용 대비 가치가 가장 높다 |
| 결과 화면 (점수 + 오답 목록) | 성취감이 나오는 지점. 점수 X/10 + 틀린 단어 목록 |
| 틀린 단어만 다시 풀기 | 오답 문항으로 재구성. 로직 재사용으로 저렴 |
| 드로어 퀴즈 모드 토글 | 사용자 요구. 자동 발음 토글과 동일 패턴 |

### Out of Scope (의도적 제외)
| 항목 | 제외 근거 |
|------|-----------|
| 한→영 문항, 듣기(TTS) 문항 | 문항 다양성은 1차 검증 후 추가. 영→한만으로 기능이 성립한다 |
| 예문 빈칸 채우기 | 예문 데이터는 있으나 blank 처리 로직(활용형 변화) 검증 필요 |
| 퀴즈 기록·정답률 추이 통계 | 새 저장 스키마와 통계 화면이 필요. 퀴즈가 실제로 쓰이는지 먼저 확인 |
| 스트릭·배지·타이머 | 게이미피케이션은 핵심 가치가 아니다 |
| SRS 간격 반복 | 단어별 숙련도 추적은 별도 대형 기능. 별표가 MVP의 대용 역할을 한다 |
| 실전 문장 모드 퀴즈 | 선택지가 긴 문장이 되어 4지선다에 부적합 |
| 독립 퀴즈 모드 (B안) | A안 검증 후 엔진 재사용으로 추가 |

**원칙**: 3줄로 되는 것을 추상화하지 않는다. 가상의 미래 요구를 위해 설계하지 않는다.

## 4. 기술 설계

### 4.1 데이터 모델 (신규)

```dart
// lib/models/quiz_question.dart
class QuizQuestion {
  final Word word;            // 정답 단어
  final List<String> options; // 뜻 4개 (정답 1 + 오답 3, 셔플됨)
  final int answerIndex;      // options 내 정답 위치
}
```

퀴즈는 세션 중에만 존재하므로 영속화하지 않는다.

### 4.2 오답 선택지 생성 (신규)

```dart
// lib/services/quiz_generator.dart
class QuizGenerator {
  List<QuizQuestion> generate({
    required List<Word> targets,   // 방금 본 세트 10단어
    required List<Word> pool,      // 오답 추출 풀 (해당 모드·레벨 전체)
    Random? random,                // 테스트 주입용
  });
}
```

**규칙**
- 오답은 `pool`에서 정답 단어를 제외하고 무작위 3개의 `meaning`을 뽑는다
- **동일 `meaning` 문자열은 배제**한다 (뜻이 겹치면 정답이 둘이 되어 문제가 성립하지 않음)
- 풀에서 서로 다른 뜻 3개를 못 채우면 해당 문항을 건너뛴다
- `pool`이 4개 미만이면 빈 리스트를 반환한다 → 호출측에서 퀴즈를 건너뛰고 기존 완료 화면 표시
- `Random` 주입으로 단위 테스트에서 결정적 검증이 가능하게 한다

**별표 모드 처리**: 별표 단어가 적을 때 오답을 만들 수 없는 문제를 피하기 위해,
별표 모드에서도 오답 풀은 전체 단어(TOEIC + OPIc)에서 뽑는다.

### 4.3 퀴즈 상태 관리 (신규)

```dart
// lib/viewmodels/quiz_controller.dart
class QuizController extends ChangeNotifier {
  List<QuizQuestion> questions;
  int currentIndex;
  int? selectedIndex;        // null이면 아직 미선택 (피드백 표시 전)
  List<Word> wrongWords;     // 오답 단어 누적

  int get score;
  bool get isFinished;
  void select(int index);    // 선택 → 채점 → 피드백 상태
  void next();               // 다음 문항 or 결과
  void retryWrongOnly();     // 오답 문항으로 재구성
}
```

`WordViewModel`은 이미 425줄이므로 퀴즈 상태를 섞지 않고 별도 컨트롤러로 분리한다.
`WordViewModel`은 퀴즈 진입 여부(`showQuiz`)와 토글 상태만 소유한다.

### 4.4 기존 파일 수정

| 파일 | 변경 내용 |
|------|-----------|
| `lib/services/favorite_service.dart` | **`add(String english)` 메서드 추가.** 현재 `toggle()`만 있어 그대로 쓰면 이미 별표된 오답 단어가 해제된다 (버그 유발 지점) |
| `lib/viewmodels/word_viewmodel.dart` | `_quizModeEnabled` 상태 + `toggleQuizMode()`, SharedPreferences 키 `quiz_mode_enabled` 저장/복원, `nextWord()` 마지막 단어 처리에서 퀴즈 진입 분기 |
| `lib/views/home_screen.dart` | 드로어에 "퀴즈 모드" Switch(자동 발음 아래), 완료 화면 위치에 퀴즈/결과 화면 분기 |

### 4.5 신규 화면

- `lib/views/quiz_view.dart` — 문항 화면 (단어 + 선택지 4개 + 피드백 + 다음 버튼)
- `lib/views/quiz_result_view.dart` — 결과 화면 (점수 + 오답 목록 + 재도전/다음 세트)

디자인은 직전에 확정된 컬러 헤더 시안(`docs/02-design/features/app-design-refresh.design.md`)의
토큰을 따른다: 헤더 `colorScheme.primary`, 흰 카드 radius 24, 알약 버튼.
정답/오답 피드백 색만 신규 토큰으로 추가한다 (정답 `#0F6E56`/`#E1F5EE`, 오답 `#A32D2D`/`#FCEBEB`).

### 4.6 플로우

```
세트 마지막 단어에서 "다음" 탭
        │
        ├─ 퀴즈 모드 OFF ─→ CompletionView (기존 동작 그대로)
        │
        └─ 퀴즈 모드 ON ──→ 문항 생성 성공? ─ No ─→ CompletionView (fallback)
                                  │
                                 Yes
                                  ↓
                          QuizView (10문항)
                          선택 → 피드백 → 다음
                          오답 발생 시 별표 add
                                  ↓
                        QuizResultView (점수 + 오답)
                            ├─ 틀린 단어만 다시 풀기 → QuizView (오답 재구성)
                            └─ 다음 세트로 → goToNextSet() (기존 동작)
```

### 4.7 결정 필요 항목

**퀴즈 모드 기본값**: 신규 기능의 발견성을 위해 **기본 ON**을 권장한다. 기존 사용자가
피로를 느끼면 드로어에서 끌 수 있고, 그 선택은 유지된다.

### 구현 중 수정한 이슈

1. **선택지 세로 정렬** — 최초 구현에서 선택지가 카드 상단에 몰려 하단 여백이 과도했다.
   문제 단어와 선택지를 한 덩어리로 묶어 카드 중앙에 배치하도록 수정.
2. **단어 카드 오버플로 (기존 버그)** — 컬러 헤더 개편으로 헤더가 높아지면서 낮은 뷰포트
